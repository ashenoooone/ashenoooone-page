# Продвижение по имени

Что уже сделано в коде: canonical, hreflang, sitemap, OG, `Person` + `WebSite` + `BlogPosting` + `BreadcrumbList` в JSON-LD, `alternateName` со всеми написаниями имени и ником.

Дальше — то, что делается руками, вне репозитория. Порядок важен: пункты 2–4 почти бесполезны, пока не сделан пункт 1.

## 1. Переехать на корень домена

Сейчас сайт живёт по адресу `ashenoooone.github.io/ashenoooone-page/` — это подпапка на чужом домене. Поисковик не считает подпапку самостоятельным сайтом: весь авторитет принадлежит `github.io`, а он размыт между миллионами проектов. Плюс `robots.txt` читается только с корня домена, поэтому лежащий в подпапке файл никто не видит (он удалён — на подпапке от него не было пользы).

**Вариант А — свой домен (лучший).** `romangontar.ru`, `gontar.dev` или подобный. Имя в домене — сильнейший сигнал для запроса по имени.

1. Купить домен.
2. `public/CNAME` с одной строкой — доменом без протокола.
3. У регистратора: `A`-записи на `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` (или `CNAME` на `ashenoooone.github.io` для поддомена).
4. В настройках репозитория: Settings → Pages → Custom domain, включить Enforce HTTPS.
5. В `astro.config.mjs`: `const BASE = '/'` и `site: 'https://<домен>'`.

**Вариант Б — юзер-сайт GitHub (бесплатно).** Репозиторий `ashenoooone.github.io` сейчас свободен — проверено, корень отдаёт 404.

1. Переименовать репозиторий в `ashenoooone.github.io`.
2. В `astro.config.mjs`: `const BASE = '/'`, `site: 'https://ashenoooone.github.io'`.

**После любого варианта** вернуть `public/robots.txt` — на корне он уже работает:

```
User-agent: *
Allow: /

Sitemap: https://<домен>/sitemap.xml
```

Со старого адреса редирект не сделать: GitHub Pages отдаёт статику без правил перенаправления. Если старый адрес уже где-то проиндексирован, единственный рычаг — «Переезд сайта» в Яндекс.Вебмастере и смена ссылок в профилях.

## 2. Подать сайт в поисковики

Без ссылок сайт сам себя не покажет — про него нужно сообщить.

**Яндекс.Вебмастер** — обязателен: по запросу «Роман Гонтарь» российская выдача идёт через Яндекс.

1. `webmaster.yandex.ru` → добавить сайт.
2. Подтверждение — HTML-файлом: положить выданный файл в `public/`, задеплоить, нажать «Проверить».
3. Индексирование → Файлы Sitemap → добавить `https://<домен>/sitemap.xml`.
4. Индексирование → Переобход страниц → отправить главную на обоих языках.
5. Через 1–2 недели проверить «Страницы в поиске» и «Диагностику».

**Google Search Console.**

1. `search.google.com/search-console` → тип «Префикс URL» (не «Домен» — он требует DNS, которого при варианте Б нет).
2. Подтверждение — HTML-файлом, так же через `public/`.
3. Sitemaps → добавить `sitemap.xml`.
4. Проверка URL → ввести адрес главной → «Запросить индексирование». То же для `/en/`.

## 3. Собрать обратные ссылки с профилей

Запрос по имени выигрывается ссылками с площадок, которые уже ранжируются по этому имени. В JSON-LD прописан `sameAs` — список профилей, но он односторонний: поисковик склеит их в одну личность только когда с профилей стоят ответные ссылки.

Проставить ссылку на сайт:

- **GitHub** — поле Website в профиле и профильный README (репозиторий `ashenoooone/ashenoooone`): там имя обоими написаниями, должность, ссылка.
- **Habr** — поле «Сайт» в профиле.
- **Telegram** — ссылка в описании канала/профиля.
- **LinkedIn** — раздел Contact info, поле Website.
- **hh.ru** — портфолио в резюме.
- **VK, dev.to, Stack Overflow** — если аккаунты живые.

Всё, что появляется в этом списке, добавлять в `socials` в `src/config/site.ts` — оттуда оно попадает и в футер, и в `sameAs`.

## 4. Дать поисковику что индексировать

Одна страница по запросу-имени ранжируется слабо. Работают регулярные заметки в блоге: каждая — отдельная страница с автором в разметке, ссылающаяся на главную. Публикации на Хабре с ссылкой на сайт дают тот же эффект и приносят внешний вес.

## Ожидания по срокам

- Индексация после подачи — от нескольких дней до 4 недель.
- Топ по своему имени — 1–3 месяца при живых ссылках с профилей.
- Быстрее всего появляется Яндекс, Google по новым доменам осторожнее.
